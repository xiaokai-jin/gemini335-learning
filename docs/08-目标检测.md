# 阶段八：目标检测

## 1. 阶段目标

本阶段在已有 RGB 图像、深度图、相机内参和图像对齐基础上，实现目标在二维图像中的检测，并为后续三维测量提供统一的检测结果。

本阶段建议按以下顺序完成：

1. 颜色分割和轮廓检测；
2. ArUco 标记识别；
3. YOLO 目标检测；
4. 多目标跟踪；
5. 将检测框、类别、置信度和深度数据结合。

目标检测只负责回答“图中有哪些目标、目标在哪里”；目标距离、尺寸和三维坐标属于阶段九。

## 2. 已具备的基础

当前项目已经具备：

- `Gemini 335` 的 Orbbec ROS2 驱动；
- RGB 图像话题；
- 深度图话题；
- 左右目和相机内参话题；
- RGB-D 软件对齐和彩色点云；
- 相机外参和坐标系信息。


## 3. 统一的数据接口

目标检测程序建议统一输出以下结构：

```text
Detection
├── class_name：目标类别
├── confidence：置信度
├── box：二维检测框 [x1, y1, x2, y2]
├── center：目标中心像素 [u, v]
├── track_id：跟踪编号，可选
├── depth：中心区域有效深度，可选
└── timestamp：图像或检测时间戳
```

统一接口可以让颜色分割、ArUco、YOLO 和跟踪共享同一套画框、状态发布和后续三维处理逻辑。

建议发布自定义 ROS2 消息，或先以普通 Python 字典和 OpenCV 显示作为原型。后续再根据项目需要发布：

```text
标注后的彩色图像：sensor_msgs/msg/Image
检测框数据：项目自定义 DetectionArray
目标中心深度：项目自定义消息或基础数据类型
目标跟踪结果：项目自定义 TrackingArray
```

当前阶段不要求每种检测方法都先有完整自定义 ROS2 消息。

## 4. 实现方式一：颜色分割

颜色分割适合学习图像处理基本流程，适合已知颜色的简单物体。

### 实现步骤

1. 订阅 `/gemini335/color/image_raw`。
2. 将图像转换为 HSV 或其他适合分割的颜色空间。
3. 根据目标颜色设置上下阈值。
4. 对掩膜执行腐蚀、膨胀和形态学闭运算。
5. 使用 `cv2.findContours()` 查找轮廓。
6. 去除面积过小的轮廓。
7. 使用最小外接矩形或外接框输出目标位置。
8. 在原图中绘制轮廓、外接框和中心点。

### 参数建议

```python
lower_color = (h_min, s_min, v_min)
upper_color = (h_max, s_max, v_max)
minimum_area = 500
```

阈值应在实际光照条件下通过滑动条调节并保存。不要把一组固定参数直接写死而不保留实验记录。

### 适用范围

- 红、蓝、绿色物体；
- 具有稳定、明显颜色的目标；
- 光照变化较小的桌面或实验环境。

颜色分割的主要问题是光照变化、相似颜色干扰和反光。后续应转向特征识别或模型检测。

## 5. 实现方式二：轮廓检测

轮廓检测适合已知形状、边缘清晰的目标，例如圆形、矩形、棋盘格和尺寸固定的物体。

### 实现步骤

1. 订阅彩色图像。
2. 转为灰度图。
3. 使用高斯模糊减少噪声。
4. 使用 Canny 边缘检测或自适应阈值得到二值图。
5. 查找轮廓。
6. 按轮廓面积筛选候选目标。
7. 使用轮廓近似判断形状。
8. 绘制外接框或轮廓点。

常见形状判断方式：

```text
3 个顶点：三角形
4 个顶点：矩形或正方形
顶点较多且圆度较高：圆形或椭圆形
轮廓面积过小：噪声，忽略
```

轮廓检测可以作为颜色分割的后处理，也可以单独识别背景相对干净的形状目标。

## 6. 实现方式三：ArUco 标记识别

ArUco 最适合用于目标定位、相机位姿估计、相对坐标验证和多目标编号。

本项目已实现 ArUco 标记检测、相机坐标系位姿估计，以及通过 TF/RViz
显示相机与标记的相对位置和姿态。这里估计的是“标记相对于相机”的位姿；
尚未计算机器人基坐标系或机械臂坐标系下的位姿。

### 实现步骤

1. 准备并固定 ArUco 标记：

   - 当前使用字典 `DICT_4X4_50`，编号范围为 `0~49`；
   - 生成的标记图片位于 `results/images/marker/`，脚本为
     `python/marker_generate.py`；
   - 当前打印标记黑色外框的实测边长为 `48.5 mm`，程序参数应填写
     `0.0485 m`；
   - 标记应平整、清晰、不反光，裁切时不要切掉黑色外框。

2. 确认安装了包含 ArUco 的 OpenCV：

```bash
python3 -c "import cv2; print(cv2.__version__, hasattr(cv2, 'aruco'))"
```

本机 OpenCV 4.5.4 使用 `cv2.aruco.detectMarkers()`、
`cv2.aruco.estimatePoseSingleMarkers()` 等 API。

3. ArUco ROS2 节点同时订阅彩色图像和相机内参：

```text
/gemini335/color/image_raw
/gemini335/color/camera_info
```

图像和 `CameraInfo` 必须属于同一个彩色相机、分辨率匹配，并且使用相同的
图像坐标系。节点在未收到有效内参或分辨率不匹配时仍可发布标记 ID 和角点，
但不会发布位姿或广播该帧的 TF。

4. 图像转换为灰度图，调用 `detectMarkers()` 获得每个标记的 ID 和四个角点。
   角点坐标是图像像素坐标，顺序为左上、右上、右下、左下。
5. 把 `CameraInfo.k` 转为相机内参矩阵 `K`，把 `CameraInfo.d` 作为畸变系数 `D`。
   同时校验内参、畸变模型、图像分辨率和 `frame_id`。
6. 调用 `estimatePoseSingleMarkers()`，输入四角像素坐标、真实标记边长、
   `K` 和 `D`，得到 Rodrigues 旋转向量 `rvec` 和平移向量 `tvec`。
7. 将 `rvec` 转为旋转矩阵和四元数；在图像上绘制标记 ID、中心点和 XYZ 轴。
8. 把位姿作为 TF 广播，并将编号、角点和位姿作为 JSON 发布。
9. 在 RViz2 中显示 TF，观察相机坐标系和标记坐标系的相对位置与旋转。

`CameraInfo` 中的：

```text
K = camera_matrix：3x3 相机内参矩阵，包含 fx、fy、cx、cy
D = distortion_coefficients：相机镜头畸变参数
```

可传给位姿估计函数。本节点订阅 `image_raw`，并直接使用相应的 `K` 和 `D`。
如果改为订阅已校正图像，需要一起确认校正后使用的相机矩阵和畸变处理方式，
避免对图像重复使用不匹配的畸变参数。

### 位姿估计原理与坐标含义

位姿估计利用“标记四个已知的平面角点在标记坐标系中的位置”和“这些角点在图像中的像素位置”，
结合相机内参及畸变模型求解透视几何（PnP）。标记实际边长确定了标记坐标系的尺度。

估计得到的变换关系可写为：

```text
X_camera = R_camera_marker * X_marker + t_camera_marker
```

- `R_camera_marker`：标记坐标轴在相机坐标系中的方向，即标记相对于相机的旋转；
- `t_camera_marker = [X, Y, Z]`：标记坐标原点在相机坐标系中的位置，单位为米；
- 标记坐标原点由 OpenCV 的单标记位姿估计定义在标记中心；
- `distance_m` 是相机光学中心到标记中心的直线距离，不等同于 Z 轴深度。

相机坐标采用 ROS optical frame 约定：

```text
X：图像向右
Y：图像向下
Z：从相机向场景前方
```

旋转输出形式：

```text
rotation_vector_rad：Rodrigues 旋转向量，单位弧度
rotation_matrix：3x3 旋转矩阵
quaternion_xyzw：ROS 顺序的四元数 x/y/z/w
```

### 位姿时间滤波

角点只有少量像素误差时，PnP 的位置和角度仍可能有变化。因此节点按标记 ID
分别平滑位姿：

- 平移使用指数移动平均：`filtered = (1 - alpha) * previous + alpha * current`；
- 旋转先转换为单位四元数，再用 SLERP 在两个姿态间插值，避免直接平均旋转向量；
- 默认 `alpha=0.7`，在平滑噪声和跟随速度间折中；
- `alpha=1.0` 表示关闭平滑；系数越小，抖动越小但动态跟随越慢；
- 标记丢失超过 `0.5 s` 后，滤波状态重置，避免标记重新出现时被旧位置拖拽；
- TF、检测 JSON 和图像坐标轴使用相同的滤波后位姿。

滤波会引入延迟，不能代替正确的相机内参、准确的标记尺寸、稳定的相机、
清晰无反光且足够大的标记图像。若坐标抖动明显，应先检查这些因素，再调低
平滑系数；若移动目标时响应滞后，应提高系数或设为 `1.0`。

### 运行和查看结果

构建并加载工作空间后，启动 ArUco 检测和 RViz：

```bash
source /opt/ros/humble/setup.bash
source /home/xiaokai/orbbec_ws/install/setup.bash
cd /home/xiaokai/gemini335-learning
colcon build \
  --base-paths ros2 \
  --build-base ros2/build \
  --install-base ros2/install \
  --packages-select gemini335_bringup
source ros2/install/setup.bash

ros2 launch gemini335_bringup gemini335.launch.py \
  enable_aruco_detection:=true \
  enable_aruco_rviz:=true \
  aruco_dictionary:=DICT_4X4_50 \
  aruco_marker_length_m:=0.0485 \
  aruco_pose_smoothing_alpha:=0.7
```

可通过 `aruco_show_windows:=false` 关闭 OpenCV 窗口。节点发布：

```text
/gemini335/detection/aruco/image：叠加边框、ID、中心和 XYZ 轴的图像
/gemini335/detection/aruco：每帧标记信息 JSON
/tf：相机到标记的实时变换
```

检测 JSON 的每个标记包含：

```text
id
corners：[左上、右上、右下、左下] 四个像素坐标
center：[u, v] 中心像素坐标
pose.translation_m：[X, Y, Z] 相机坐标系位置，单位米
pose.rotation_vector_rad：旋转向量，单位弧度
pose.rotation_matrix：3x3 旋转矩阵
pose.quaternion_xyzw：四元数
pose.distance_m：相机到标记中心的直线距离，单位米
camera_info_valid：相机内参是否对当前图像有效
pose_valid：当前帧是否成功估计了位姿
```

TF 的父坐标系是彩色图像 `header.frame_id`，子坐标系默认命名为
`aruco_marker_<ID>`。子坐标系原点在标记中心，轴向代表估计出的标记旋转。
如需查询某个标记相对于相机的变换：

```bash
ros2 run tf2_ros tf2_echo gemini335_color_optical_frame aruco_marker_0
```

若实际图像 `frame_id` 与示例不同，应将 `tf2_echo` 的父 frame 替换成实际值。
RViz 默认 Fixed Frame 为 `gemini335_color_optical_frame`；若提示 frame 不存在，
先检查 `/gemini335/color/image_raw` 的 `header.frame_id`，再在 RViz 的
`Global Options → Fixed Frame` 中选择该实际 frame。

成功检测并收到有效内参后，RViz 的 TF 显示会出现相机和标记坐标轴。若画面内有
多个相同 ID 的标记，它们会争用同一个 TF 子 frame；因此一个 ID 应只对应一个
同时可见的实体标记。

## 7. 实现方式四：YOLO 目标检测

YOLO适合类别较多、目标外观复杂或需要通用目标检测的场景。

### 运行架构

```text
Gemini 335
  -> /gemini335/color/image_raw
  -> ROS2 Python/C++ 检测节点
  -> YOLO 推理
  -> 检测框和类别
  -> 叠加在 RGB 图像上
  -> 发布标注图像或自定义检测消息
```

### 选择模型

初期建议：

- 使用预训练模型验证数据流；
- 优先使用较小模型，保证实时性；
- 最终再根据目标类别和精度需求选择模型；
- 在 Gemini 335 数据集上微调，而不是直接假设预训练模型适用于实际场景。

### 检测节点职责

检测节点只负责：

- 接收彩色图像；
- 图像格式转换；
- 模型推理；
- 置信度和类别筛选；
- 重叠框过滤；
- 发布检测结果；
- 绘制可视化结果。

不要把相机初始化、模型训练和三维坐标计算全部写在一个脚本中。它们应作为独立阶段存在。

### 推理环境

根据实际设备选择：

```text
CPU 推理：验证流程，速度较低
GPU 推理：需要确认 CUDA 和 PyTorch 环境
OpenVINO：可用于优化并部署
TensorRT：适合后续在 NVIDIA 平台上部署
```

本阶段应先保证端到端结果正确，再进行模型量化、加速和部署优化。

## 8. 自定义数据集

只有目标类别不是通用模型类别，或实际场景差异较大时才需要采集数据集。

### 数据集步骤

1. 固定相机并启动彩色图像。
2. 采集目标正面、侧面、遮挡、远近和不同光照图像。
3. 保存原始图像到 `results/images/` 或独立数据目录。
4. 使用标注工具标注目标外接框。
5. 按 `train / val / test` 分割。
6. 生成训练框架所需的标注格式。
7. 训练并在验证集上检查。
8. 在真实相机画面上测试。
9. 根据漏检、误检和速度记录进行迭代。

每个类别建议使用不同角度和距离的数据，不能只用屏幕照片或静态背景下的单张照片。

### 数据集目录示例

```text
datasets/
└── object_detection/
    ├── images/
    │   ├── train/
    │   ├── val/
    │   └── test/
    ├── labels/
    │   ├── train/
    │   ├── val/
    │   └── test/
    └── dataset.yaml
```

标注工具、类别数量和文件格式应以实际训练框架为准。

## 9. 多目标跟踪

跟踪用于连接相邻帧中的检测框，减少类别抖动并为每个目标提供稳定 ID。

### 可先实现的跟踪流程

1. 每帧执行检测，得到多个检测框。
2. 提取检测框中心点或完整目标特征。
3. 对上一帧目标与当前检测框进行匹配。
4. 使用中心距离、IoU 或外观特征计算相似度。
5. 为匹配目标保留或更新 `track_id`。
6. 为新目标创建 `track_id`。
7. 对连续未匹配目标设定最大丢失帧数。
8. 超过丢失帧数后删除旧跟踪目标。

初学阶段建议先使用基于 IoU 或中心距离的跟踪器，不要一开始叠加复杂的 Re-ID 模型。

## 10. 图像坐标与深度坐标

检测框中心或内部区域可以用于关联深度。

深度取值建议：

1. 先取目标中心附近区域，而不是只取一个像素；
2. 去除 `0`、异常值和超出相机有效距离范围的深度；
3. 使用有效深度的中位数或截断均值；
4. 通过与 `depth_camera_info` 对应的 `fx, fy, cx, cy` 做反投影；
5. 将三维坐标转换到目标机器人的基坐标系属于后续阶段。

反投影公式：

```text
X = (u - cx) * Z / fx
Y = (v - cy) * Z / fy
Z = depth(u, v)
```

公式中的相机内参必须与使用的图像分辨率和坐标系对应。

## 12. 建议实现顺序

### 第一阶段：颜色分割

- 完成真实相机画面订阅；
- 完成 HSV 分割；
- 完成轮廓筛选；
- 输出目标中心和面积；
- 保存一个成功案例和一个失败案例。

验收标准：

- 固定光照下目标可以稳定检测；
- 未知物体或相似颜色不会大量误检；
- 中心像素稳定输出。

### 第二阶段：轮廓和形状

- 完成二值化；
- 完成轮廓筛选；
- 区分矩形、圆形或其他形状；
- 为相似轮廓设置面积阈值。

验收标准：

- 噪声和小轮廓能够被过滤；
- 已知形状能在多帧中稳定检测。

### 第三阶段：ArUco

- 完成标记打印、张贴或固定；
- 完成标记检测；
- 完成标记编号和角点输出；
- 完成相机坐标系位姿估计；
- 使用已知距离验证平移向量。

验收标准：

- 多个标记可以按 ID 区分；
- 位姿估计结果不会因为轻微角度变化大幅抖动；
- 已知距离和估计距离误差在预期范围内。

### 第四阶段：YOLO

- 完成预训练模型推理；
- 完成 ROS2 图像到模型输入的转换；
- 完成检测框筛选；
- 完成标注图像发布；
- 根据需要采集并标注数据；
- 完成自训练模型的验证。

验收标准：

- 验证集上目标类别、置信度和框位置合理；
- 实际相机画面中漏检和误检可量化；
- 能在目标硬件上达到可接受帧率。

### 第五阶段：跟踪

- 为每个检测目标提供稳定编号；
- 完成目标进入、离开和遮挡后的处理；
- 输出跟踪目标的速度、轨迹或历史位置。

验收标准：

- 短暂遮挡后可以恢复原 ID；
- 多目标交叉时不会频繁交换 ID；
- 静止目标不会因为检测抖动不断生成新 ID。

## 13. 实验记录

每个检测方法至少记录：

- 相机分辨率；
- 相机帧率；
- 启动参数；
- 使用的算法和模型；
- 参数或置信度阈值；
- 有效检测距离；
- 漏检、误检和遮挡情况；
- 处理帧率；
- 示例图像或视频；
- 与阶段九三维测量的接口状态。

实验结果建议保存到：

```text
results/images/
results/videos/
results/detection/
```

## 14. 常见问题

### ROS2 图像无法转换

检查：

- 图像话题是否正在发布；
- 消息类型是否为 `sensor_msgs/msg/Image`；
- 是否使用了相同的编码；
- 是否安装并配置了 `cv_bridge`；
- 程序中是否释放了已停止图像话题。

### 检测框抖动

检查：

- 图像分辨率是否过低；
- 是否缺少形态学处理；
- 模型置信度阈值是否过低；
- 是否可以使用时间滤波或跟踪器；
- 相机是否稳定；
- 是否存在自动曝光和快速光照变化。

### 深度和检测框无法对应

检查：

- 彩色图像和深度图是否来自相同分辨率；
- 是否启用了深度注册；
- 深度图是否已经按照彩色相机校准；
- 程序中是否使用了对应相机的 `CameraInfo`；
- 检测框坐标是否按原始或校正图像缩放。

### YOLO 速度过低

检查：

- 图像是否可以适当降采样；
- 模型是否过大；
- 是否使用了 GPU 或优化推理；
- 是否关闭了不需要的可视化；
- 是否存在重复推理或重复预处理；
- 深度和点云处理是否占用了过多资源。

## 15. 阶段验收

完成本阶段后，应至少具备：

- 可运行的实时 RGB 图像检测程序；
- 至少一种二维目标检测方法；
- 检测框、类别和置信度的统一数据结构；
- 稳定的目标中心像素输出；
- 可复现的参数和启动命令；
- 多目标检测和跟踪的实验记录；
- 已验证的检测与深度数据接口；
- 成功和失败案例截图；
- 下一阶段三维测量所需的检测结果。

完成本阶段后进入阶段九：三维测量，实现：

- 目标到相机的距离；
- 目标宽度、高度和三维坐标；
- 不同距离下的测量误差；
- 检测框与点云或深度图的完整联动。
