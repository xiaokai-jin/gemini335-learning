# 阶段八：目标检测

## 1. 阶段目标

本阶段在已有 RGB 图像、深度图、相机内参和图像对齐基础上，实现目标在二维图像中的检测，并为后续三维测量提供统一的检测结果。

本阶段建议按以下顺序完成：

1. 颜色分割和轮廓检测；
2. ArUco 标记识别；
3. YOLO 目标检测；
4. 多目标跟踪；
5. 将检测框、类别、置信度和深度数据结合。

目标检测只负责回答“图中有哪些目标、目标在哪里”；目标距离、尺寸和三维坐标属于阶段九。

## 2. 已具备的基础

当前项目已经具备：

- `Gemini 335` 的 Orbbec ROS2 驱动；
- RGB 图像话题；
- 深度图话题；
- 左右目和相机内参话题；
- RGB-D 软件对齐和彩色点云；
- 相机外参和坐标系信息。

启动相机时建议使用软件对齐：

```bash

source /home/xiaokai/orbbec_ws/install/setup.bash
source /home/xiaokai/gemini335-learning/ros2/install/setup.bash

  depth_registration:=true \

```

优先确认以下话题：

```bash
ros2 topic list | grep -E 'color|depth|camera_info|points'
```

常用话题包括：

```text

/gemini335/depth/image_raw

```

对齐深度话题名称可能由当前驱动版本决定，应先用 `ros2 topic list` 实际确认，不应直接假设固定名称。

## 3. 统一的数据接口

目标检测程序建议统一输出以下结构：

```text
Detection
├── class_name：目标类别
├── confidence：置信度
├── box：二维检测框 [x1, y1, x2, y2]
├── center：目标中心像素 [u, v]
├── track_id：跟踪编号，可选
├── depth：中心区域有效深度，可选
└── timestamp：图像或检测时间戳
```

统一接口可以让颜色分割、ArUco、YOLO 和跟踪共享同一套画框、状态发布和后续三维处理逻辑。

建议发布自定义 ROS2 消息，或先以普通 Python 字典和 OpenCV 显示作为原型。后续再根据项目需要发布：

```text
标注后的彩色图像：sensor_msgs/msg/Image
检测框数据：项目自定义 DetectionArray
目标中心深度：项目自定义消息或基础数据类型
目标跟踪结果：项目自定义 TrackingArray
```

当前阶段不要求每种检测方法都先有完整自定义 ROS2 消息。

## 4. 实现方式一：颜色分割

颜色分割适合学习图像处理基本流程，适合已知颜色的简单物体。

### 实现步骤

1. 订阅 `/gemini335/color/image_raw`。
2. 将图像转换为 HSV 或其他适合分割的颜色空间。
3. 根据目标颜色设置上下阈值。
4. 对掩膜执行腐蚀、膨胀和形态学闭运算。
5. 使用 `cv2.findContours()` 查找轮廓。
6. 去除面积过小的轮廓。
7. 使用最小外接矩形或外接框输出目标位置。
8. 在原图中绘制轮廓、外接框和中心点。

### 参数建议

```python
lower_color = (h_min, s_min, v_min)
upper_color = (h_max, s_max, v_max)
minimum_area = 500
```

阈值应在实际光照条件下通过滑动条调节并保存。不要把一组固定参数直接写死而不保留实验记录。

### 适用范围

- 红、蓝、绿色物体；
- 具有稳定、明显颜色的目标；
- 光照变化较小的桌面或实验环境。

颜色分割的主要问题是光照变化、相似颜色干扰和反光。后续应转向特征识别或模型检测。

## 5. 实现方式二：轮廓检测

轮廓检测适合已知形状、边缘清晰的目标，例如圆形、矩形、棋盘格和尺寸固定的物体。

### 实现步骤

1. 订阅彩色图像。
2. 转为灰度图。
3. 使用高斯模糊减少噪声。
4. 使用 Canny 边缘检测或自适应阈值得到二值图。
5. 查找轮廓。
6. 按轮廓面积筛选候选目标。
7. 使用轮廓近似判断形状。
8. 绘制外接框或轮廓点。

常见形状判断方式：

```text
3 个顶点：三角形
4 个顶点：矩形或正方形
顶点较多且圆度较高：圆形或椭圆形
轮廓面积过小：噪声，忽略
```

轮廓检测可以作为颜色分割的后处理，也可以单独识别背景相对干净的形状目标。

## 6. 实现方式三：ArUco 标记识别

ArUco 最适合用于目标定位、相机位姿估计、相对坐标验证和多目标编号。

当前阶段先实现标记检测，不要求加入机械臂坐标变换。

### 实现步骤

1. 安装 OpenCV ArUco 模块：

```bash
pip install opencv-contrib-python
```

2. 选择一种明确的字典，例如 `DICT_5X5_100`。
3. 订阅彩色图像。
4. 使用当前 OpenCV API 创建字典和检测器参数。
5. 检测标记角点和标记 ID。
6. 根据图像尺寸和相机内参估计标记位姿。
7. 绘制标记边框、编号和坐标轴。

`CameraInfo` 中的：

```text
camera_matrix
distortion_coefficients
```

可传给位姿估计函数。图像校正后，若仍使用原始畸变参数，需要确认是否重复校正。

### 位姿估计参数

位姿估计需要知道标记的真实边长。例如标记边长为 `0.05 m`，则函数返回：

- 标记旋转向量；
- 标记平移向量；
- 目标相机坐标系中的三维位置。

标记编号可以用于区分多个目标。先固定标记、记录真实坐标，再验证检测结果。

## 7. 实现方式四：YOLO 目标检测

YOLO适合类别较多、目标外观复杂或需要通用目标检测的场景。

### 运行架构

```text
Gemini 335
  -> /gemini335/color/image_raw
  -> ROS2 Python/C++ 检测节点
  -> YOLO 推理
  -> 检测框和类别
  -> 叠加在 RGB 图像上
  -> 发布标注图像或自定义检测消息
```

### 选择模型

初期建议：

- 使用预训练模型验证数据流；
- 优先使用较小模型，保证实时性；
- 最终再根据目标类别和精度需求选择模型；
- 在 Gemini 335 数据集上微调，而不是直接假设预训练模型适用于实际场景。

### 检测节点职责

检测节点只负责：

- 接收彩色图像；
- 图像格式转换；
- 模型推理；
- 置信度和类别筛选；
- 重叠框过滤；
- 发布检测结果；
- 绘制可视化结果。

不要把相机初始化、模型训练和三维坐标计算全部写在一个脚本中。它们应作为独立阶段存在。

### 推理环境

根据实际设备选择：

```text
CPU 推理：验证流程，速度较低
GPU 推理：需要确认 CUDA 和 PyTorch 环境
OpenVINO：可用于优化并部署
TensorRT：适合后续在 NVIDIA 平台上部署
```

本阶段应先保证端到端结果正确，再进行模型量化、加速和部署优化。

## 8. 自定义数据集

只有目标类别不是通用模型类别，或实际场景差异较大时才需要采集数据集。

### 数据集步骤

1. 固定相机并启动彩色图像。
2. 采集目标正面、侧面、遮挡、远近和不同光照图像。
3. 保存原始图像到 `results/images/` 或独立数据目录。
4. 使用标注工具标注目标外接框。
5. 按 `train / val / test` 分割。
6. 生成训练框架所需的标注格式。
7. 训练并在验证集上检查。
8. 在真实相机画面上测试。
9. 根据漏检、误检和速度记录进行迭代。

每个类别建议使用不同角度和距离的数据，不能只用屏幕照片或静态背景下的单张照片。

### 数据集目录示例

```text
datasets/
└── object_detection/
    ├── images/
    │   ├── train/
    │   ├── val/
    │   └── test/
    ├── labels/
    │   ├── train/
    │   ├── val/
    │   └── test/
    └── dataset.yaml
```

标注工具、类别数量和文件格式应以实际训练框架为准。

## 9. 多目标跟踪

跟踪用于连接相邻帧中的检测框，减少类别抖动并为每个目标提供稳定 ID。

### 可先实现的跟踪流程

1. 每帧执行检测，得到多个检测框。
2. 提取检测框中心点或完整目标特征。
3. 对上一帧目标与当前检测框进行匹配。
4. 使用中心距离、IoU 或外观特征计算相似度。
5. 为匹配目标保留或更新 `track_id`。
6. 为新目标创建 `track_id`。
7. 对连续未匹配目标设定最大丢失帧数。
8. 超过丢失帧数后删除旧跟踪目标。

初学阶段建议先使用基于 IoU 或中心距离的跟踪器，不要一开始叠加复杂的 Re-ID 模型。

## 10. 图像坐标与深度坐标

检测框中心或内部区域可以用于关联深度。

深度取值建议：

1. 先取目标中心附近区域，而不是只取一个像素；
2. 去除 `0`、异常值和超出相机有效距离范围的深度；
3. 使用有效深度的中位数或截断均值；
4. 通过与 `depth_camera_info` 对应的 `fx, fy, cx, cy` 做反投影；
5. 将三维坐标转换到目标机器人的基坐标系属于后续阶段。

反投影公式：

```text
X = (u - cx) * Z / fx
Y = (v - cy) * Z / fy
Z = depth(u, v)
```

公式中的相机内参必须与使用的图像分辨率和坐标系对应。

## 12. 建议实现顺序

### 第一阶段：颜色分割

- 完成真实相机画面订阅；
- 完成 HSV 分割；
- 完成轮廓筛选；
- 输出目标中心和面积；
- 保存一个成功案例和一个失败案例。

验收标准：

- 固定光照下目标可以稳定检测；
- 未知物体或相似颜色不会大量误检；
- 中心像素稳定输出。

### 第二阶段：轮廓和形状

- 完成二值化；
- 完成轮廓筛选；
- 区分矩形、圆形或其他形状；
- 为相似轮廓设置面积阈值。

验收标准：

- 噪声和小轮廓能够被过滤；
- 已知形状能在多帧中稳定检测。

### 第三阶段：ArUco

- 完成标记打印、张贴或固定；
- 完成标记检测；
- 完成标记编号和角点输出；
- 完成相机坐标系位姿估计；
- 使用已知距离验证平移向量。

验收标准：

- 多个标记可以按 ID 区分；
- 位姿估计结果不会因为轻微角度变化大幅抖动；
- 已知距离和估计距离误差在预期范围内。

### 第四阶段：YOLO

- 完成预训练模型推理；
- 完成 ROS2 图像到模型输入的转换；
- 完成检测框筛选；
- 完成标注图像发布；
- 根据需要采集并标注数据；
- 完成自训练模型的验证。

验收标准：

- 验证集上目标类别、置信度和框位置合理；
- 实际相机画面中漏检和误检可量化；
- 能在目标硬件上达到可接受帧率。

### 第五阶段：跟踪

- 为每个检测目标提供稳定编号；
- 完成目标进入、离开和遮挡后的处理；
- 输出跟踪目标的速度、轨迹或历史位置。

验收标准：

- 短暂遮挡后可以恢复原 ID；
- 多目标交叉时不会频繁交换 ID；
- 静止目标不会因为检测抖动不断生成新 ID。

## 14. 常见问题

### ROS2 图像无法转换

检查：

- 图像话题是否正在发布；
- 消息类型是否为 `sensor_msgs/msg/Image`；
- 是否使用了相同的编码；
- 是否安装并配置了 `cv_bridge`；
- 程序中是否释放了已停止图像话题。

### 检测框抖动

检查：

- 图像分辨率是否过低；
- 是否缺少形态学处理；
- 模型置信度阈值是否过低；
- 是否可以使用时间滤波或跟踪器；
- 相机是否稳定；
- 是否存在自动曝光和快速光照变化。

### 深度和检测框无法对应

检查：

- 彩色图像和深度图是否来自相同分辨率；
- 是否启用了深度注册；
- 深度图是否已经按照彩色相机校准；
- 程序中是否使用了对应相机的 `CameraInfo`；
- 检测框坐标是否按原始或校正图像缩放。

### YOLO 速度过低

检查：

- 图像是否可以适当降采样；
- 模型是否过大；
- 是否使用了 GPU 或优化推理；
- 是否关闭了不需要的可视化；
- 是否存在重复推理或重复预处理；
- 深度和点云处理是否占用了过多资源。

## 15. 阶段验收

完成本阶段后，应至少具备：

- 可运行的实时 RGB 图像检测程序；
- 至少一种二维目标检测方法；
- 检测框、类别和置信度的统一数据结构；
- 稳定的目标中心像素输出；
- 可复现的参数和启动命令；
- 多目标检测和跟踪的实验记录；
- 已验证的检测与深度数据接口；
- 成功和失败案例截图；
- 下一阶段三维测量所需的检测结果。

完成本阶段后进入阶段九：三维测量，实现：

- 目标到相机的距离；
- 目标宽度、高度和三维坐标；
- 不同距离下的测量误差；
- 检测框与点云或深度图的完整联动。
