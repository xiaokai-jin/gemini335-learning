# 阶段六：RGB-D 图像对齐

## 目标

理解 RGB 图像和深度图为什么需要对齐，以及如何使用 Orbbec 驱动提供的对齐功能。

## 1. 什么是图像对齐

Gemini 335 的彩色相机和深度相机位置不同、分辨率不同，因此同一个物体在 RGB 图像和深度图中的像素位置不一定相同。

图像对齐就是利用相机内部的标定参数，将 RGB 和深度数据映射到同一个坐标系，使下面的关系成立：

```text
RGB 像素 <-> 对应的深度值 <-> 三维坐标
```

## 2. 是否需要自己实现

通常不需要。

Gemini 335 和 Orbbec ROS2 驱动已经提供：

- 相机内参；
- RGB 与深度相机外参；
- 畸变参数；
- 深度计算；
- RGB-D 对齐；
- 彩色点云生成。

我们主要负责：

1. 启动对应功能；
2. 订阅正确的话题；
3. 检查图像和点云是否对齐。

文档中的公式主要用于理解原理，不要求当前阶段自己编写对齐算法。

## 3. 当前项目如何使用

普通原始图像：

```text
/gemini335/color/image_raw
/gemini335/depth/image_raw
```

这两路图像不一定像素一一对应。

彩色点云：

```text
/gemini335/depth_registered/points
```

驱动会自动把深度点投影到 RGB 图像，并为三维点添加颜色。

当前 Gemini 335 建议使用软件对齐：

```bash
ros2 launch gemini335_bringup gemini335.launch.py \
  enable_colored_point_cloud:=true \
  depth_registration:=true \
  align_mode:=SW
```

## 4. 硬件对齐和软件对齐

- `HW`：相机或 SDK 使用硬件完成对齐，速度较快，但要求特定的分辨率组合；
- `SW`：驱动在电脑端完成对齐，兼容性更好，但会占用一些 CPU。

当前项目使用：

```text
align_mode:=SW
```

如果使用硬件对齐时出现下面的错误：

```text
Current stream profile is not support hardware d2c process
```

改用软件对齐即可。

## 5. 如何简单验证

查看彩色点云是否发布：

```bash
ros2 topic list | grep depth_registered
ros2 topic hz /gemini335/depth_registered/points
```

在 RViz2 中添加：

```text
/gemini335/depth_registered/points
```

如果物体颜色能够正确覆盖在三维点云上，说明对齐基本正常。

## 小结

阶段6只需要掌握：

- RGB 和深度图不能直接按像素复制；
- 相机和驱动会自动完成标定与对齐；
- 当前项目使用 `align_mode:=SW`；
- 彩色点云是对齐结果的直观体现。
