# 阶段七：相机内外参

## 目标

理解 ROS2 `CameraInfo` 和 Orbbec `Extrinsics` 中各参数的含义，并把实际输出还原成内参矩阵、投影矩阵、畸变参数、旋转矩阵和平移向量。

本阶段只学习和读取相机出厂标定参数，暂不进行重新标定。

## 1. 查看参数话题

内参和畸变参数来自 `camera_info`：

```bash
ros2 topic echo /gemini335/color/camera_info --once
ros2 topic echo /gemini335/depth/camera_info --once
ros2 topic echo /gemini335/left_ir/camera_info --once
ros2 topic echo /gemini335/right_ir/camera_info --once
```

RGB-D 外参来自：

```bash
ros2 topic echo /gemini335/depth_to_color --once
ros2 topic echo /gemini335/depth_to_left_ir --once
ros2 topic echo /gemini335/depth_to_right_ir --once
```

## 2. 内参矩阵 K

ROS2 `CameraInfo.k` 按行排列 9 个数：

```text
k = [fx, 0, cx,
     0, fy, cy,
     0,  0,  1]
```

矩阵形式为：

```text
K = [ fx  0  cx
       0 fy  cy
       0  0   1 ]
```

含义：

- `fx`：水平方向焦距，单位是像素；
- `fy`：垂直方向焦距，单位是像素；
- `cx`：主点横坐标；
- `cy`：主点纵坐标。

### RGB 相机实际数据

RGB 图像尺寸为 `1280×720`，输出为：

```text
k =
[691.929931640625, 0, 646.1608276367188,
 0, 692.1031494140625, 364.02239990234375,
 0, 0, 1]
```

因此：

```text
K_color =
[691.9299   0       646.1608
 0         692.1031 364.0224
 0         0         1]
```

### 左目 IR 相机实际数据

左目图像尺寸为 `1280×800`：

```text
K_left =
[619.28125  0         634.5
 0         619.28125 397.0
 0           0          1]
```

### 右目 IR 相机实际数据

右目内参为：

```text
K_right =
[619.28125  0         634.5
 0         619.28125 397.0
 0           0          1]
```

左右目内参相同或非常接近是正常的，但它们的相对位置不同，所以右目投影矩阵中会出现基线项。

## 3. 畸变参数 D

ROS2 `CameraInfo.d` 是畸变参数数组。常见针孔模型排列为：

```text
D = [k1, k2, p1, p2, k3]
```

其中：

- `k1, k2, k3`：径向畸变；
- `p1, p2`：切向畸变。

当前 RGB、左目和右目输出的 `d` 都是 8 个零：

```text
D = [0, 0, 0, 0, 0, 0, 0, 0]
```

这表示当前驱动输出的图像已经按其配置视为无畸变，或者畸变参数没有单独提供。使用时应以驱动发布的 `CameraInfo` 为准，不要自行补充畸变参数。

## 4. 校正矩阵 R

ROS2 `CameraInfo.r` 是 3×3 校正旋转矩阵：

```text
R = [r00 r01 r02
     r10 r11 r12
     r20 r21 r22]
```

当前输出为单位矩阵：

```text
R_rect =
[1 0 0
 0 1 0
 0 0 1]
```

这表示当前消息没有额外施加图像校正旋转。注意，这个 `CameraInfo.r` 是单个相机图像校正使用的矩阵，不等于 RGB 相机和深度相机之间的外参旋转矩阵。

## 5. 投影矩阵 P

ROS2 `CameraInfo.p` 是 3×4 投影矩阵：

```text
P = [fx'  0   cx'  Tx
      0  fy'  cy'  Ty
      0   0    1    0]
```

它用于把相机坐标系中的三维点投影到图像：

```text
[u, v, 1]^T ~ P [X, Y, Z, 1]^T
```

### RGB 相机投影矩阵

当前 RGB 输出：

```text
P_color =
[691.9299   0       646.1608  0
 0         692.1031 364.0224  0
 0           0         1       0]
```

### 右目投影矩阵

当前右目输出：

```text
P_right =
[619.28125  0         634.5        0
 0         619.28125 397.0         0
 0           0         1           0]
```

但实际输出中的 `p[3]` 为 `-31.162912109375`。完整写法是：

```text
P_right =
[619.28125  0         634.5       -31.1629121
 0         619.28125 397.0         0
 0           0         1            0]
```

在双目模型中：

```text
Tx = -fx * B
```

因此：

```text
B = -Tx / fx
  = 31.1629121 / 619.28125
  ≈ 0.05032 m
  ≈ 50.32 mm
```

这与 Gemini 335 规格中的约 `50 mm` 基线一致。

## 6. RGB-D 外参

Orbbec 外参消息包含：

```text
rotation
translation
```

外参变换为：

```text
P_target = R * P_source + t
```

其中 `R` 是 3×3 旋转矩阵，`t` 是 3×1 平移向量。

### depth -> color

实际输出的 `rotation` 按行还原为：

```text
R_depth_to_color =
[ 0.9999826550   0.0041269963  -0.0042055664
 -0.0041313730  0.9999909401  -0.0010325235
  0.0042012669  0.0010498803   0.9999906421]
```

`translation` 为：

```text
t_depth_to_color =
[-0.014102895
 -0.000011056
 -0.002050799] m
```

所以：

```text
P_color = R_depth_to_color * P_depth + t_depth_to_color
```

平移量约为：

```text
X: -14.10 mm
Y: -0.01 mm
Z: -2.05 mm
```

它表示按照驱动定义的坐标方向，深度坐标系中的点转换到 RGB 坐标系时需要进行这组平移和旋转。

### depth -> left_ir

实际输出：

```text
R_depth_to_left =
[1 0 0
 0 1 0
 0 0 1]

t_depth_to_left =
[0
 0
 0] m
```

说明驱动把深度坐标系与左目 IR 坐标系作为同一参考坐标系，或当前消息使用了这一坐标定义。

### depth -> right_ir

实际输出：

```text
R_depth_to_right =
[1 0 0
 0 1 0
 0 0 1]

t_depth_to_right =
[-0.0503211
  0
  0] m
```

表示右目相对于左目/深度参考坐标系沿 X 方向约偏移 `50.32 mm`，这就是双目基线的外参表达。

## 7. frame_id 的注意事项

你输出的 `/gemini335/depth/camera_info` 中出现了：

```text
frame_id: gemini335_color_optical_frame
```

而深度图尺寸是 `1280×800`。这说明当前驱动可能在深度注册或彩色点云配置下，把深度相关信息关联到了彩色坐标系。不要只根据话题名称猜测坐标系，应该同时检查：

```bash
ros2 topic echo /gemini335/depth/camera_info --once
ros2 topic echo /gemini335/depth/image_raw --once
ros2 topic echo /gemini335/depth_registered/points --once
ros2 topic echo /tf_static --once
```

后续进行坐标变换时，以消息中的 `header.frame_id` 和 TF 为准。


## 8. 当前阶段结论

当前不需要重新标定。驱动已经提供了：

- RGB、深度、左右 IR 的 `CameraInfo`；
- RGB 和深度之间的外参；
- 深度和左右 IR 之间的外参；
- TF 静态坐标变换；
- 双目基线信息。

阶段七需要掌握的是如何读取这些数据，并理解它们如何组成矩阵、完成投影和坐标变换。实际应用时优先使用驱动发布的参数，不要手动改写。
