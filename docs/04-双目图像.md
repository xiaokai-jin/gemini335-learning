# 阶段四：双目图像

## 目标

使用 ROS2 获取 Gemini 335 的左目和右目红外图像，观察同一场景在两个相机中的位置差异，并理解双目深度与 RGB-D 深度的区别。

Gemini 335 的左右目是红外（IR）图像，不是彩色图像。Orbbec 驱动已经完成底层 USB 采集和 ROS2 发布，本项目只需要在 launch 中打开两个 IR 流。

## 1. 启动左右目

每个新终端先加载工作空间：

```bash
source /opt/ros/humble/setup.bash
source /home/xiaokai/orbbec_ws/install/setup.bash
source /home/xiaokai/gemini335-learning/ros2/install/setup.bash
```

启动相机：

```bash
ros2 launch gemini335_bringup gemini335.launch.py \
  enable_left_ir:=true \
  enable_right_ir:=true
```

当前 launch 已显式指定左右目和深度均为 `1280 x 800 @ 30 FPS`。左右目与深度必须使用相同的分辨率和帧率。如果需要切换到其他相机支持的组合，必须同时修改三者，例如：

```bash
ros2 launch gemini335_bringup gemini335.launch.py \
  left_ir_width:=1280 left_ir_height:=800 left_ir_fps:=30 \
  right_ir_width:=1280 right_ir_height:=800 right_ir_fps:=30 \
  depth_width:=1280 depth_height:=800 depth_fps:=30
```

如果参数设为 `0`，表示交给驱动自动选择；本相机曾自动选择 `848 x 480 @ 30 FPS`。如果指定的组合不被相机支持，驱动可能启动失败，应以启动日志为准。

彩色点云需要深度到彩色对齐。Gemini 335 当前建议使用软件对齐：

```text
depth_registration:=true
align_mode:=SW
```

## 2. 左右目话题

默认话题为：

```text
/gemini335/left_ir/image_raw
/gemini335/right_ir/image_raw
```

检查话题是否存在：

```bash
ros2 topic list | grep -E 'left_ir|right_ir'
ros2 topic info /gemini335/left_ir/image_raw
ros2 topic info /gemini335/right_ir/image_raw
ros2 topic hz /gemini335/left_ir/image_raw
ros2 topic hz /gemini335/right_ir/image_raw
```

使用 `rqt_image_view` 查看：

```bash
sudo apt install ros-humble-rqt-image-view
ros2 run rqt_image_view rqt_image_view
```

在窗口中分别选择两个话题。左右窗口应看到相同场景，但物体在水平方向存在位置差异，这个位置差就是视差的直观表现。

也可以使用 `image_view` 保存图像：

```bash
sudo apt install ros-humble-image-view
ros2 run image_view image_saver --ros-args \
  -r image:=/gemini335/left_ir/image_raw
ros2 run image_view image_saver --ros-args \
  -r image:=/gemini335/right_ir/image_raw
```

## 3. 双目视觉和视差
讲解网址：https://zhuanlan.zhihu.com/p/668965054
双目相机由两个具有已知相对位置的相机组成。设左、右相机光心距离为基线 `B`，经过标定得到焦距 `f`。同一个空间点投影到校正后的左右图像中，横坐标分别为 `u_left` 和 `u_right`，则视差为：

```text
d = u_left - u_right
```

在理想的水平极线校正后，同一个点只需要在同一行搜索，匹配问题从二维搜索简化为一维搜索。针孔模型给出深度：

```text
Z = f * B / d
```

其中：

- `Z`：点到相机坐标系的前向距离；
- `f`：像素单位的焦距；
- `B`：左右相机基线；
- `d`：视差，必须使用与 `f` 相同的像素单位。

因此，近处物体的视差较大，远处物体的视差较小；视差接近零时，深度误差会明显增大。误差传播近似为：

```text
|delta Z| ≈ (f * B / d^2) * |delta d|
```

这解释了双目在远距离处通常不如近距离稳定。

### 实际计算流程

1. 对左右相机分别去畸变；
2. 使用内参和左右相机外参进行立体校正；
3. 在左右图像中寻找同一像素对应点；
4. 计算视差图；
5. 通过 `Z = fB/d` 转换为深度图；
6. 对遮挡、低纹理、反光和匹配错误进行过滤。

左右图像本身只包含亮度信息，不能直接把左右像素相减当作深度。必须有相机标定参数和可靠的对应点匹配。Gemini 335 的驱动通常已经利用左右 IR 传感器计算并发布深度图；本阶段先验证原始左右图像，后续再实现 OpenCV 立体匹配。

## 4. 双目深度和 RGB-D 深度的区别

| 项目 | 双目深度 | RGB-D 深度 |
|---|---|---|
| 测量来源 | 两个相机图像的对应点和视差 | RGB-D 设备的深度传感器输出 |
| 典型原理 | 被动立体匹配，或红外纹理辅助匹配 | 常见为结构光、主动红外或 ToF |
| 关键参数 | 左右内参、畸变、基线、外参、匹配算法 | 深度传感器标定、调制/投影参数和解码算法 |
| 对纹理依赖 | 纯被动双目依赖纹理；红外投影可改善低纹理场景 | 主动投影通常对低纹理表面更友好 |
| 远距离表现 | 视差变小，深度误差容易变大 | 取决于传感器量程和噪声模型 |
| 透明/反光物体 | 可能匹配失败或产生错误对应 | 也可能受反射、透射和多径影响 |
| 输出关系 | 可由左右图像重新计算深度 | 驱动直接发布深度图；左右图像可作为辅助数据 |

Gemini 335 的“深度图”与“左右 IR 图像”不是同一份消息：左右 IR 图像是原始观测，深度图是设备/驱动经过标定和匹配处理后的结果。RGB 图像则是另一个彩色相机的结果。若要把深度映射到 RGB，还需要 RGB 与深度相机之间的外参和对齐过程，不能直接按像素坐标复制。

## 5. 常见问题

- **话题不存在**：确认 launch 文件已经重新构建并 source，且两个 `enable_*_ir` 参数为 `true`。
- **只有一侧有数据**：检查 USB 连接、相机支持的 IR 配置和驱动启动日志。
- **左右图像亮度不同**：左右传感器曝光、增益和红外响应可能不同，不代表视差计算一定错误。
- **左右图像无法直接叠加**：两个相机有不同内参和畸变，应该先做立体校正。
- **左右图像时间不一致**：双目匹配需要尽量同步；本项目 launch 默认开启 `enable_frame_sync`。
